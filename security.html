the framework

An AppSec program is a chair. It stands on four legs.

Too many programs still run like it's 2008: triaging scanner output, filing tickets, chasing single vulnerabilities like they're snowflakes. That's project management with extra steps. The mission is to turn security from a blocker into an accelerator, and to fix systemic flaws at scale instead of one bug at a time. I wrote the framework up in full; this is the shape of it.

leg 1
Security by default

Tiered SAST guardrails with an AI false-positive filter between rule and PR. Custom rules for your own anti-patterns. Dependency policy with auto-merged patches. Threat modeling that happens at planning, for every project, automatically. Paved roads: see a flaw class three times, build the safe primitive and flag the unsafe one.

leg 2
Reactionary security

The human pass. Design review for the high-risk projects the default threat model surfaces, pentest findings, bug bounty, incident follow-through. Small by design, because leg 1 keeps most things from ever reaching it.

leg 3
Security by design

Secure primitives, reference architectures, and libraries that make the right thing the easy thing: an HTTP client that refuses internal ranges and enforces timeouts, an auth helper that handles tenant scoping.

leg 4
Continuous feedback & metrics

Every override is auditable and feeds the loop. Rules earn the right to block with a measured false-positive rate. The program reports on what it changed, not on how many tickets it filed.
